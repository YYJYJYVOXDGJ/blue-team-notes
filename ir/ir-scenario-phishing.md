# S9 钓鱼邮件与社交工程

> 定位：**P1**（无交互行为）／**P2 起步、确认点击后升 P1**（已点链接或已下载附件）。
> 本场景是 `ir-scenarios.md` 的第 9 个分支，结构沿用统一模板：**识别信号 → 10 分钟确认 → 遏制（含禁忌）→ 清除与根因 → 恢复与加固 → 复盘要点**。
>
> **本场景的特殊之处**：真正紧急的往往不是主机，而是**账号**。主机排查是"确认有没有后手"，
> 账号处置才是止损主线。顺序搞反了，主机查得再干净也没用。

---

## 0. 先纠正三个常见误判

在动手之前先建立正确预期，避免把力气花在错的地方：

| 常见误判 | 实际情况 |
|---|---|
| "收到钓鱼邮件 = 电脑中毒了" | **不会**。邮件正文不是可执行文件。只要没点链接、没下载附件、没启用宏，单纯收到邮件本身几乎不可能导致失陷 |
| "先杀毒再改密码" | **反了**。密码泄露的影响面远大于单台主机；主机可以慢慢查，密码必须马上改 |
| "把可疑文件删掉就安全了" | **删错比留着麻烦**。看不懂的条目先记下来，别删 |

## 1. 识别信号

### 1.1 邮件侧

- 显示名与发信域不一致（显示"某平台官方"，`Return-Path` 却是随机域名）
- SPF / DKIM 校验为 `fail` 或 `softfail`，或无 DKIM 签名
- 制造紧迫感：限时确认、附件伪装成"岗位说明/订单/发票"、索要银行卡或验证码
- 正文准确喊出收件人姓名、单位、岗位职责（说明是定向而非广撒网）
- 链接为短链，或形如 `platform-login.example.com` 的仿冒域名

### 1.2 主机侧（已发生交互后才会有）

- 浏览器 / Office 进程派生出 `cmd.exe`、`powershell.exe`
- 新增启动项、计划任务指向 `AppData` / `Temp` / `ProgramData`
- 出向连接到陌生 IP 的典型远控端口
- 邮箱被添加自动转发规则或收信规则（**最常见的后手**）

## 2. 10 分钟确认

### 2.1 判读邮件头（最关键的一步，且必须在网页版邮箱里做）

在网页版邮箱中打开原邮件，找「显示原始邮件 / 查看邮件头 / 原件」，重点看三行：

```text
Return-Path:  退信地址，真正决定这封信从哪个域发出
Received:     经过的服务器链路，从下往上读，最下面是最初发信源
X-Mailer:     用什么程序/服务发的，群发平台会在这里露馅
```

| 像垃圾营销（大概率无害） | 像定向钓鱼（要警惕） |
|---|---|
| Return-Path 是可查的大型邮件服务商 | Return-Path 为随机拼凑域名，或与显示名完全无关 |
| Received 链路清晰，SPF / DKIM 显示 pass | SPF=fail / softfail，无 DKIM 签名 |
| 正文是通用话术，不含收件人具体信息 | 准确喊出姓名、单位、投递过的岗位 |
| 链接指向平台官方域名 | 链接是短链，或仿冒域名（多一个 `-login`、换后缀） |
| 只是"点击查看内容" | 制造紧迫感：24 小时内确认、附件是说明文档、索要银行卡 |

> **注意**：招聘类、电商类平台把信息卖给第三方、或用第三方邮件服务商群发，是行业常态。
> "收到代发广告"本身**不构成**定向攻击的证据，判断必须回到邮件头的三行上。

```bash
# 查域名真假（复制出来查，不要点！）
nslookup 域名
whois 域名
```

域名注册时间不足一个月、注册信息全部隐藏 → 高度可疑。

### 2.2 主机侧快速确认

```powershell
# 有无异常出向（重点看 ESTABLISHED）
netstat -ano | findstr ESTABLISHED

# 进程命令行与父进程 —— 抓邮件触发型木马最有效的一招
powershell -NoProfile -Command "Get-CimInstance Win32_Process | Select-Object ProcessId,ParentProcessId,Name,CommandLine | Format-List"
```

父进程判据：`cmd.exe` / `powershell.exe` 的父进程若为 `winword.exe`（Word）、`excel.exe`、`outlook.exe`，
说明由邮件附件触发，**高度可疑**。

完整排查流程见 [`windows/windows-manual-steps.md`](../windows/windows-manual-steps.md)；
需要留证时跑 `scripts/windows-ir-quickcheck.ps1`。

## 3. 遏制（含禁忌）

### 3.1 已点链接 / 已下载附件时的 5 步止损

1. **断网**。拔网线或关 WiFi，阻断可能的远控通信。**不要关机**——关机丢失内存证据。
2. **换一台干净设备改密码**（手机最安全）。优先级：邮箱 → 同密码的其他账号 → 其他平台账号。
3. **检查邮箱的自动转发与过滤规则**。这是钓鱼最常见的后手：不改密码，而是加一条转发规则长期偷看邮件。
   路径：邮箱设置 → 收信规则 / 自动转发 / 过滤，逐条核对。
4. **检查邮箱登录记录**。主流邮箱均提供"最近登录记录"，看有无异地或陌生设备。
5. **再跑主机排查 + 全盘杀毒**。

### 3.2 绝对不要做的事

- 不要在邮件里点任何链接，**包括"退订"按钮**——退订链接常被用来确认邮箱是活跃的
- 不要下载 `.exe` / `.scr` / `.js` / `.zip` / `.iso` / `.html` 附件，不要启用 Office 宏
- 不要回复、不要回骂——回复等于告诉对方"这个邮箱有人看"
- **不要下载来路不明的"专杀工具""系统清理大师"**。恐慌状态下装的第二个软件，往往才是真正的毒
- 不要照着网上教程乱删注册表、乱停服务——停错服务会开不了机
- **不要格式化重装来逃避问题**。重装不解决账号已被盗
- 若确认已中招，**不要在受检的这台机器上输入新密码**，用手机改

正确做法：标记垃圾邮件 + 拉黑发件域，然后不管它。

## 4. 清除与根因

### 4.1 本机排查清单（A–G）

| 项 | 查什么 | 可疑判据 |
|---|---|---|
| A 网络 | `netstat -ano` | 非常规端口（4444/6666/8080/9001）的外连；关闭所有程序后仍有稳定外连 |
| B 进程 | 命令行与父进程 | 路径在 `AppData`/`Temp`/`ProgramData`；命令行含 base64 或 `-enc` |
| C 持久化 | Run 键、计划任务、服务、启动文件夹 | 路径指向 `AppData`/`Temp`/`ProgramData`/`Public` |
| D 文件 | 最近下载、Temp 下可执行文件 | 随机名（如 `a8f3c2.exe`）、伪装系统名但不在 System32 |
| E 账号 | `net user`、`net localgroup administrators` | 陌生账号；管理员组多了人 |
| F 劫持 | hosts、系统代理、DNS 缓存 | hosts 出现指向邮箱/金融/招聘站点的记录；`ProxyEnable` 非 0 |
| G 日志 | 安全日志 4624/4625/4720/4732 | 深夜陌生登录；4720 新建账号、4732 加入管理员组 |

逐条命令与完整判据见 [`windows/windows-manual-steps.md`](../windows/windows-manual-steps.md)。

### 4.2 远程控制软件排查

在「设置 → 应用 → 已安装的应用」中检索以下名字，凡不记得安装过的一律视为问题：

`AnyDesk`、`TeamViewer`、`ToDesk`、`向日葵`、`RustDesk`、`Ammyy`

### 4.3 杀毒与系统修复

```cmd
:: 快速扫描（几分钟）
"%ProgramFiles%\Windows Defender\MpCmdRun.exe" -Scan -ScanType 1
:: 全盘扫描（1–3 小时）
"%ProgramFiles%\Windows Defender\MpCmdRun.exe" -Scan -ScanType 2

:: 系统文件完整性（无害，跑了没坏处）
sfc /scannow
DISM /Online /Cleanup-Image /RestoreHealth
```

扫出的威胁让杀软**隔离**而非直接删除——隔离可还原，删错不可逆。

## 5. 恢复与加固

- 邮箱开启**二次验证**（短信或 Authenticator）——这一条比什么都管用
- 清除邮箱中不认识的**自动转发 / 收信规则 / 第三方应用授权**
- 修改所有与邮箱同密码的账号；梳理该密码的使用范围并全部更换
- 浏览器检查扩展，删除不记得安装的；清除已保存密码并重新设置
- 若为**公司设备或工作邮箱**，上报 IT / 安全部门，不要自行处置

---

## 6. 复盘要点

| 复盘项 | 要回答的问题 |
|---|---|
| 入口 | 是广撒网还是定向？依据是什么（回到邮件头三行） |
| 交互程度 | 是否点过链接、下过附件、启用过宏？决定了处置等级 |
| 账号影响面 | 哪些账号使用了同密码？是否已全部更换 |
| 后手 | 邮箱转发规则、持久化项、远控软件是否清理干净 |
| 检测能力 | 邮件网关是否拦得住？主机侧为何没告警 |
| 人的因素 | 是否需要补充钓鱼识别培训；是否有可用的上报通道 |

---

## 7. 十分钟的极简版

如果上面全部看不进去，至少做这 6 件：

1. 邮件删除 / 拉黑，**不点任何东西**
2. **用手机**改邮箱密码 + 开二次验证
3. 邮箱设置里检查**自动转发和收信规则**
4. 其他使用同密码的账号一并修改
5. 跑一次 `netstat -ano | findstr ESTABLISHED`，看有无陌生外连
6. 跑一次杀软全盘扫描

> **本文所有命令均为系统自带工具，只读为主。** 涉及删除、修改、重装的操作前请先备份重要数据，
> 并确认自己知道在做什么。拿不准的结果不要自行处置，把输出提交给分析人员研判。
