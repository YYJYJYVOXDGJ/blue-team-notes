## 脱敏规范（**新增案例必须遵守**）

本仓库是**公开仓库**。任何案例在入库前必须过一遍下面的清单，逐项确认。

### 一、必须删除或泛化（红线）

| 信息类别 | 示例 | 处理 |
|---|---|---|
| 主机名 / 域名 | `WIN-HOST-01`、`corp.local` | 泛化为 `HOST-A`、`example.local` |
| 用户名 / 账号 | `C:\Users\zhangsan\` | 泛化为 `C:\Users\<用户>\` |
| 内网 IP 与网段 | `10.0.0.0/8`、`192.168.x.x` | 换成 RFC 5737 文档保留段：`192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24` |
| 公网 IP（**本机资产**） | 受检主机的出网地址 | 一律删除或保留段替换 |
| 邮箱 / 手机号 / 姓名 / 单位 | — | 一律删除 |
| 设备画像 | 本机装了哪些软件、硬件型号 | 除分析对象本身外一律删除 |
| 业务数据 | 数据库名、表名、文件内容片段 | 一律泛化 |
| 第一人称叙事 | "你当时的怀疑""上一轮我" | 改为中性案例体 |

### 二、可以保留（**并建议保留**）

| 信息类别 | 理由 |
|---|---|
| 公网 IP（**第三方/厂商基础设施**，非涉事资产） | 属公开可查情报，RDAP 可验证；是结论可复现的依据。但**建议隐去数值、保留 ASN 归属结论**，避免对特定主体作公开定性 |
| PID、端口号、事件 ID、注册表路径 | 无身份关联性 |
| 系统自带命令与输出格式 | 通用知识 |
| 公开来源的引用（论文、公开分析报告） | 增强可信度，注明来源 |
| 时间（精确到月即可） | 体现时效性，无身份关联性 |

### 三、判断原则

> **问自己一个问题：这条信息能否反过来定位到具体的人或组织？**
>
> - 能 → 删或泛化
> - 不能，且是结论成立的必要依据 → 保留，并在文档中说明保留理由
>
> **拿不准就删。** 案例的教学价值来自于推理结构，不来自于具体数值。

### 四、厂商与产品名的处理

对特定厂商或产品作公开定性表述存在风险，本案例集统一采用**泛化命名**：

- `<OEM>` —— 硬件/软件厂商
- `<Component>` —— 组件或产品名
- `<Account>`、`<Log>` —— 按角色命名的模块

泛化不影响推理结构的可复用性：**判定一个组件是否恶意，依据的是路径、签名、ASN 三项硬证据，而不是它的名字。**

## 新增案例模板

```markdown
# 案例 0XX · <一句话现象>

> **案例类型**：<误报排除 / 真实事件 / 检测盲区>
> **平台**：<Windows / Linux / 云>
> **关联**：<关联的排查步骤与规则 ID>

## 1. 初始发现与误判      ← 写清楚当初为什么判断错了
## 2. 定性：<N>维对比表    ← 硬证据逐项对照
## 3. 它到底是什么         ← 整目录/整链路拆解
## 4. 为什么会这样         ← 行为归因
## 5. 方法论教训           ← 本案例最该看的一节
## 6. 可复用步骤
## 7. 处置结论
## 附 · 本案例的脱敏处理   ← 逐项列出改了什么、为什么
```

**不要只写做对了的部分。** 把判断被推翻的过程写下来，才是有价值的案例。
